# Полный статус helox terminal 0.20.0

Дата отчёта: 13 октября 2026 года. Версия 0.20.0 завершает запланированное развитие инструмента: основной упор сделан на самостоятельное восстановление сохранённой конфигурации после входа в Windows, сохранение выбранной мыши и восстановление после прерванных записей. Это законченная локальная утилита настройки и диагностики мыши. Совместимость с будущими изменениями Windows, драйверов и игр нельзя гарантировать одним финальным релизом.

## Что представляет собой инструмент

helox работает в Windows 10/11 через меню терминала и команды. Базовая часть использует .NET Framework 4.x. Для игровых преобразований ввода подключается официальный подписанный Raw Accel 1.7.1; нужны 64-битная Windows, совместимые .NET/Visual C++ компоненты, права администратора для установки и перезагрузка. Свой драйвер ядра проект не создаёт.

Обработка ввода выполняется драйвером, поэтому держать терминал открытым после настройки не требуется. Приложение не создаёт аккаунт, не отправляет телеметрию, не читает память игры, не делает захват экрана, не определяет цели и не генерирует движение мыши. Опциональный помощник при входе в Windows запускается один раз, проверяет условия восстановления и завершает работу.

## Что работает

| Возможность | Что именно выполняется |
| --- | --- |
| Выбор мыши | перечисление устройств Raw Input; сохранение выбранного в меню пути; отказ от подмены отключённой мыши другой |
| Настройки Windows | скорость указателя, ускорение с сохранением порогов, прокрутка, интервал двойного щелчка и обмен кнопок |
| Профили | сохранение полных настроек Windows, просмотр изменений, применение, отмена последнего изменения и восстановление оригинала |
| Измерение ввода | фактическая частота доставки отчётов, медиана/p95/p99 интервалов, длинные паузы, признаки пакетной доставки и история выбранной мыши |
| Оценка DPI | подсчёт полученных перемещений на известном расстоянии; для GXT 929 доступна приблизительная трёхпроходная оценка по длине корпуса |
| Ускорение | естественная кривая и собственная ограниченная таблица чувствительности с базой, началом/концом перехода, пределом и формой |
| Фильтры | независимое усреднение выходной величины, стабильность коэффициента ускорения, ослабление малых движений, привязка к осям и коэффициенты направлений |
| Игровые настройки | Valorant, CS2 и три варианта Kovaak's; стили balanced/steady/linear, редактируемые эффекты, личный диапазон скорости и общий undo |
| Проверка отклика | расчёт официальным движком, сравнение текущих и предлагаемых настроек, коррекция после флика и разворота, учёт дробного остатка |
| Возобновление | ручное `aim resume` и опциональное восстановление сохранённых aim-параметров при входе в Windows |
| Диагностика | проверка файлов backend, службы и стека выбранной мыши, активной конфигурации, восстановления, автозапуска и доступных журналов Windows |
| Обслуживание | проверяемое восстановление оригиналов, удаление общего драйвера и очистка собственных данных с предварительными проверками |

Windows-настройки относятся к рабочему столу. Игры с Raw Input обходят ускорение указателя Windows, но могут получать преобразованные драйвером отсчёты. helox не меняет чувствительность, FOV и конфигурационные файлы игры: необходимые действия описывает игровой checklist.

## Что закрывает 0.20.0

Выбранная в меню мышь сохраняется между запусками. Если она отключена, программа сообщает об этом и сохраняет привязку; произвольный запасной ввод не становится новой целью настройки. Командные `select` и `--mouse` остаются временными, чтобы разовая диагностика не меняла обычный выбор.

Добавлено добровольное восстановление aim-настроек при входе в систему: `startup on`, `startup off`, `startup status`, `startup run`. Для текущего пользователя регистрируется скрытый `bin\helox-startup.exe` в разделе Run; Windows может отложить его запуск или отключить через свои настройки автозагрузки. В обычном запуске терминала сохранённые параметры сами не применяются. Помощник допускает автоматическое восстановление только при проверенных условиях: уже совпадающий выбранный профиль не переписывается; иначе вся конфигурация драйвера должна соответствовать исходным значениям после сброса. Чужая изменённая конфигурация, текущий bypass и параметры других мышей сохраняются. При обнаруженных поддерживаемых играх, недоступном запросе процессов, недоступной мыши или незавершённом восстановлении работа пропускается. Это снижает необходимость каждый раз вручную выполнять `aim resume`, но сохраняет диагностируемый отказ при неоднозначных условиях.

Помощник использует последние сохранённые aim-эффекты и калибровку/временные параметры, зафиксированные при включении. `startup.json` хранит привязку, а `startup-last.json` — последний результат. После переноса папки, смены USB-пути мыши или осознанного изменения программной калибровки нужно заново выполнить `startup on`. Фонового повторения попыток нет: если мышь появилась позже проверки, можно выполнить ручное возобновление.

Проверка игр ограничена известными именами процессов Valorant, CS2 и Kovaak's. Другие игры и запуск игры после проверки этим механизмом не подтверждены. Bypass — состояние живого драйвера, не сохранённый параметр возобновления: после сброса/перезагрузки включённый helper может снова включить сохранённый профиль. Чтобы эффекты оставались отключёнными между входами в систему, выполнить `startup off`, затем `aim bypass on`. Сам по себе bypass не переживает сброс ядровой конфигурации.

Обычные изменения Windows получают собственный `windows-recovery.json`; восстановление выполняется командой `recover`. Aim-записи используют общий проверяемый checkpoint, доступный через `preset recover`. Проверка живого драйвера имеет отдельное `aim verify restore`. После ошибки или закрытия процесса программа не должна молча продолжать новые изменения, потеряв исходный снимок. Контрольные файлы удаляются после успешного восстановления необходимых компонентов.

Инструкции приведены к текущему меню; устаревшие внутренние номера фильтров и старые пути измерений заменены видимыми действиями. Полный рабочий порядок собран в [operation and recovery](operations.md).

Поставка тоже завершена: архив содержит оба исполняемых файла, исходники, тесты, документацию, инструкции сборки и обслуживания. `release-manifest.json` перечисляет размер и SHA256 каждого включённого файла; рядом с zip публикуется `helox-terminal-v0.20.0.zip.sha256`. Проверка `verify-package.ps1` обнаруживает отсутствующие, изменённые, лишние и связанные файлы. Манифест подтверждает целостность распаковки, а происхождение архива проверяется сравнением SHA256 с опубликованным релизом; сам манифест не является цифровой подписью. После собственной пересборки сравнение бинарников с исходным манифестом закономерно перестаёт совпадать.

Сборка компилирует оба бинарника до замены установленных копий, блокирует одновременные сборки одной папки и пытается вернуть прежний helper, если консольный файл занят. Упаковка проверяет версию собранного приложения и пытается вернуть прежнюю пару zip/контрольной суммы при ошибке публикации. После обычного завершения временная staging-папка удаляется; если дополнительная блокировка мешает самому откату, резервные файлы сохраняются, а ошибка сообщает их путь. Launcher проверен с путями, содержащими пробелы и скобки, и запуском из другой рабочей директории.

Подготовка официального backend проверяет цепочки путей и отказывается ремонтировать кэш через junction/symlink; сохранённый upstream settings-файл не затирается. Совпадающие занятые файлы можно повторно использовать, а изменённый занятый файл останавливает ремонт и требует закрыть приложение перед повтором. Более ранние файлы к этому моменту уже могли быть восстановлены, но неуспешная подготовка не переходит к установке или удалению драйвера. Загрузка имеет ограничение по времени, проверенный новый zip атомарно заменяет прежний кэш. Эти проверки не требуют переустановки уже работающего драйвера.

## Где заканчиваются возможности программы

**Аппаратные DPI, установленный polling rate, заряд батареи, RGB и питание мыши остаются неизвестными.** Из наличия приёмника нельзя вывести, включена ли сама мышь. HID-дескриптор без физических единиц не сообщает DPI. Для проверенного GXT 929 известны размеры корпуса и возможности дескриптора, однако подтверждённого протокола записи аппаратных параметров нет. Произвольные команды в приёмник не отправляются.

Измеряемый Hz — частота доставленного Windows ввода во время движения, а не чтение настройки USB. Остановка руки и прерывание радиоканала могут выглядеть одинаково. Пакетная доставка влияет на интервалы. DPI-калибровка — оценка полученных отсчётов на расстоянии; она зависит от измерения пути и блокируется при обнаруженном или неопределённом преобразовании ввода.

Фильтры не восстанавливают потерянные радиоотчёты, ошибочное направление сенсора и физический spinout. Усреднение выходной величины добавляет задержку и способно усилить маленькую коррекцию сразу после флика. Micro damping ослабляет полезные медленные коррекции вместе с нежелательным дрожанием. Snapping меняет направление движения. Существование фильтра не делает его обязательным улучшением; сравнивать нужно при одинаковых DPI и чувствительности.

Тест модели подтверждает расчёт конфигурации, проверка ядра — записанные параметры, а захват Raw Input — регистрацию и доставку событий. Это разные уровни доказательства. Ни один сам по себе не доказывает улучшение результата в игре, точность физического сенсора, принятие каждой конфигурации Vanguard или разрешение настройки на турнире. Служба Vanguard и процесс игры проверяются без их запуска.

Снимки восстановления помогают при прерывании процесса. Они не гарантируют сохранность при поломке диска, внезапной потере питания, удалении данных вручную или вмешательстве другого приложения. Настройки Raw Accel общие для драйвера: полный оригинальный снимок и undo могут затрагивать другие его устройства, что указано в инструкциях.

## Как пользоваться после финального обновления

1. Распаковать релиз в постоянную папку и открыть `launch.bat`.
2. Один раз выбрать мышь в `6 more > 1 choose mouse`.
3. При необходимости установить официальный драйвер и перезагрузиться.
4. Применить подходящий игровой рецепт или свою кривую, проверив сравнение отклика.
5. Выполнить `startup on`, если нужно восстановление после входа в Windows; проверить `startup status` после первого входа.
6. Закрыть терминал и пользоваться мышью. Для чтения состояния доступны `health`, `aim status`, `preset status`.

После изменения физического DPI проверить ощущение и построить новую персональную настройку при необходимости. Запись движения для нового личного диапазона считается актуальной семь дней. Уже сохранённые полные aim-параметры можно возобновлять без нового захвата. При отключении помощника команда `startup off` не отменяет текущие эффекты; для них есть bypass, undo и restore.

При незавершённой операции использовать команду, указанную в диагностике: `recover`, `preset recover` или `aim verify restore`. При неудаче сохранить папку `%localappdata%\helox-terminal` и текст ошибки; удаление checkpoint вручную лишает программу части информации для возврата.

Перед обычным удалением драйвера отключается восстановление при входе. Полная очистка ждёт завершения терминала, отказывается работать при активном helper/другой сессии, возвращает доступные оригиналы и отключает автозапуск перед удалением данных. Неуспешное удаление или восстановление сообщает ошибку и сохраняет оставшиеся данные; после удаления загруженного драйвера может потребоваться перезагрузка.

## Проверки и доказательства

Результаты именно релиза 0.20.0 фиксируются в [verification](verification.md#final-operation-and-recovery--0200). Предыдущие записи в этом файле относятся к соответствующим историческим релизам и не заменяют проверку новой версии. Hosted CI проверяет сборку, чистые регрессии, скрипты обслуживания и упаковку; реальные изменения Windows и драйвера проверяются отдельно на интерактивном компьютере с последующим восстановлением исходного состояния.

Проверки 13 октября 2026 года:

| Проверка | Подтверждённый результат |
| --- | --- |
| Полный `tests/run.ps1` | прошёл: официальный движок расчёта, запись/чтение/возврат настроек Windows, чистые регрессии, команды, меню, профили, undo, скрипты обслуживания, launcher и упаковка |
| Отдельный `tests/final-live.ps1` | прошёл: восстановление после принудительного завершения desktop-записи и десять сценариев startup; исходное полное состояние восстановлено |
| Расширенный `tests/live.ps1` | прошёл: 13 записей/проверок драйвера и 21 цикл применения/отмены рецептов, независимые фильтры, отказ от устаревшего preview и восстановление после ошибок/принудительных выходов |
| Наследование модулей PowerShell 7 | пропущено: `pwsh.exe` отсутствует; воспроизведение именно этой среды локально не выполнено |
| Реальная перезагрузка и вход в Windows | не выполнялись; проверены отдельный скрытый helper и искусственно восстановленное исходное состояние драйвера |
| Физический сенсор и фактический игровой ввод | не подтверждены; `GameInputVerified` остаётся null |

Сценарии startup проверяют совпадающий профиль без повторной записи, восстановление сброшенного драйвера, сохранение программной DPI-нормализации 1600 и постоянного расчётного интервала 1000 Hz, применение последнего сохранённого snapping и отказ при чужой конфигурации, bypass, recovery, отключённой мыши или выключенном автозапуске. Проверен откат регистрации при неудачном `startup off`. Значения DPI/Hz в этих случаях относятся к вычислению драйвера и не являются чтением аппаратных настроек. После теста подтверждено восстановление драйвера, настроек Windows, сохранённых файлов и собственного значения автозапуска HKCU; сам тест не оставляет помощник включённым вместо прежнего состояния.

Живая проверка также подтвердила отмену изменений только сохранённых предпочтений, отсутствие повторной активации уже совпадающего рецепта, независимые smoothing/flick-tail, точное восстановление метаданных, выходы посреди precision/bypass/восстановления оригинала, возврат испорченных saved-файлов побайтно и отказ от повреждённого undo. Полные исходные настройки драйвера, Windows и байты сохранённых файлов восстановлены до выдачи успешного результата. В этом запуске пассивный захват получил 0 отчётов движения. Синхронная активация заняла 1007 мс и сразу прошла чтение полной конфигурации; это время записи параметров, а не задержка движения мыши.

`tests/commands.ps1` предназначен для CI и выполняет только чтение/проверку контрактов; `tests/final-live.ps1` запускается отдельно на локальном компьютере с закрытыми играми. CI не выполняет эту живую проверку.

Физическая сравнительная проверка сенсора, DPI по независимому измерению расстояния, ощущений в игре и прохождения преобразованного потока внутри матча остаётся ручной. Формулировка «тесты прошли» не распространяется автоматически на эти пункты.

## Репозиторий и дальнейший статус

Официальный репозиторий — [maximkochergin/helox-terminal](https://github.com/maximkochergin/helox-terminal), основная ветка `main`, лицензия MIT. Перед работой над 0.20.0 проверены история коммитов, предыдущие GitHub Releases, Issues, Pull Requests и последние сборки: открытых и закрытых Issues/PR на момент проверки не было; последние десять CI-запусков завершились успешно. Исторический стиль — короткие английские коммиты строчными буквами, заголовок релиза `v<version> / <description>`, zip и SHA256. [Релизы проекта](https://github.com/maximkochergin/helox-terminal/releases).

0.20.0 закрывает плановую разработку функций. Новые функциональные обновления не запланированы. Код, история и релизы доступны; архивирование репозитория этим релизом не выполняется. Будущая смена Windows, правил подписывания драйверов, античита или внешних зависимостей может потребовать исправления совместимости или безопасности. Заявлять, что обновления технически больше никогда не понадобятся, было бы неверно.

Текущий разумный итог: программа завершена в рамках подтверждённого доступа к Windows и официальному драйверу, умеет сохранить конфигурацию, повторно применить её при понятных условиях, проверить результат и восстановиться после прерванных записей. Неподтверждённые аппаратные функции и обещания игрового результата не маскируются под готовые возможности.
